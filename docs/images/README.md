Web 页面地址为 `/en/weather/shenzhen-1795565`，采集服务为本机 `http://127.0.0.1:3300`。天气来自实际服务返回的 Open-Meteo 快照，原生页面可能使用自己的有效缓存；不同截图的温度和更新时间不要求相同，也不能用于判断当前天气。手机浏览器图使用移动视口，并不代表 Safari 真机验收。

地图使用默认 OSM 标准栅格瓦片。界面控件已切换英文，底图保留当地地名，因此深圳周边仍显示中文。这反映真实供图能力，没有为了“全英文”截图替换测试瓦片或隐藏底图。需要英文地名时，应配置实际英文样式并单独验证其覆盖范围。

`Ask weather` 为 AI 天气问答入口。Web 使用 Vercel AI SDK，Flutter 使用 `ai_ui_stream`，通过同一 SSE 协议支持流式接收、逐字显示、中断生成、失败重试与连续追问。`web-ask.png` 展示初始面板，`web-ask-answering.png` 展示实际回答逐字显示过程；流式、重试和中断能力的完整验证见根 README 链接的既有问答验收报告。

补图使用实际问题 `What is the current temperature in Shenzhen?`，没有拦截或替换问答响应，也没有修改截图中的文字。最终请求返回 `200 text/event-stream`，页面显示 `AI INTERPRETATION`，拍摄时处于 `Displaying answer…` 状态；完成后提供 1 条预报依据，页面异常为 0。采集脚本和结构化记录为本机忽略目录中的 `qa/evidence/readme-ai-answer-capture.ts`、`readme-ai-answering.json`。这次补图只验证该次问答，不代表重新完成全部问答验收。

补图前两次采集未成功：首轮等待“至少 50 字符且仍在显示”超时，未留存当时完整页面状态，不能据此确定应用原因；第二轮误将页面级播报节点当成问答错误而提前退出。限定只读取问答弹窗内的错误节点后，最终采集成功。前两次日志保留为 `readme-ai-answering-first.log`、`readme-ai-answering-second.log`；三次采集均各发送一次问答，最终记录对应最后一次。

## 采集过程

1. Web 使用 Playwright 打开英文深圳城市深链，分别以桌面和窄屏视口截图；普通搜索输入 `Shenzhen`，等待匹配结果后截图，再点击首条结果，确认回到 `/en/weather/shenzhen-1795565` 且标题为 `Shenzhen`。地图等待真实瓦片加载，问答等待弹层动画完成。
2. iOS 从已有问答页返回首页，通过应用语言菜单选择 `English`，保留当前深圳与原有对话，再用 `xcrun simctl io … screenshot --type=png` 采集。
3. Android 使用已有安装，从深圳首页进入搜索，再打开地图，通过 `adb exec-out screencap -p` 采集；完成后返回首页。
4. 逐张检查城市、英文控件、图片尺寸及署名，检查根 README 的本地代码、文档与图片引用。

原始采集脚本与日志保留在本机忽略目录 `qa/evidence/`，包括 `readme-ui.swift`、`readme-ui-build.log`。最初 iOS 采集脚本把 Flutter 合并的无障碍节点当作独立 `StaticText`，因此元素断言失败；实际语言已切换成功，最终截图经过目视核对。没有把采集脚本失败记为应用语言功能失败，也没有将本轮采集当作新一轮完整业务验收。
