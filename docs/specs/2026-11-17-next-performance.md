# Next.js 切城性能优化规格

## 目标与边界

在现有生产构建上减少其他城市的点击等待，复用有效天气；保留首页默认定位、四语可索引 HTML、城市快照的一致性和地图按需加载。沿用天气 15 分钟新鲜期、3 小时旧数据上限，不启用全站静态天气缓存。

## 验收条件

- P1：其他城市按收藏顺序，仅在前两项进入视野后闲时预取；更多城市在悬停、聚焦或触摸时准备页面。省流量、离线、隐藏页面和慢网不执行自动预取。大量收藏不能造成全部预取。
- P2：已访问城市的有效完整快照直接提供摘要，缺失摘要仍每批最多 20 座。预取不调用模型、定位或地图瓦片。
- P3：搜索、地图、问答仅在用户表达操作意图后提前加载模块。首屏地图瓦片为零，后台模块预热失败不破坏点击重试。
- P4：完整预取的路由缓存有明确有效期；旧路由快照不能覆盖更新的本机快照，超过天气新鲜期时显示旧数据标记并刷新。城市、时区、依据使用同一快照。
- P5：生产构建前后至少五轮交替测量，分别记录点击至目标天气、首屏 JS、后台 RSC 传输和上游次数。完成四宽度、四语、定位、问答草稿和原始 HTML 的受影响回归，并更新交付包与取舍记录。

## 实施依据

已阅读当前安装的 Next.js 16.4.6 的 `prefetching`、`Link`、`useRouter` 与 `staleTimes` 文档。动态天气路由使用文档支持的 `Link prefetch={true}` 获取完整页面；默认自动模式不足以准备完整动态预报。现有请求级 React cache、共享文件天气缓存、地图懒加载继续复用。

## 非目标

本轮不修改 Flutter 与原生二进制，不更换天气服务或真实 AI 配置，不以本地受控延迟推算公网速度。公网 SEO、流量和真机结果沿用原验收边界。
