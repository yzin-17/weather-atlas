# SEO 全面巡检与修复

## 目标与边界

按用户要求检查当前 Weather Atlas 的 SEO 遗漏和不合理行为，直接修复本机可验证问题，复测并更新取舍记录、源码与证据包。以当前脏工作区和运行中的 HTTP／HTTPS 为基线，保留其他工具链修改、原生二进制和既有证据。此前首页允许索引、四语和原坐标隐私约定持续有效。

不以本地检查替代公网部署、GSC、搜索展示或真实流量；不引入虚构评分、组织、天气富结果、搜索行为或文档修改时间。

## 验收约定

- AC1：4 首页＋24 城市页在普通浏览器、Googlebot、分享爬虫的原始 HTML 中具有唯一、正确的标题／描述／canonical／robots／语言互链／JSON-LD；sitemap 28 个规范 URL，逐项验证有效性、互指和可访问性。客户端语言／城市／历史导航不能残留上一页标记。
- AC2：`SITE_URL` 明确支持站点根的 HTTP／HTTPS 源；拒绝凭据、非 HTTP 协议、子路径、查询和片段，不静默截断配置；生产缺少地址应明确报错，开发缺省使用本项目端口。不根据请求 Host 推断公开 canonical。
- AC3：根路径按实际支持语言和 Accept-Language 权重选择，尊重 q=0 和稳定默认，响应包含正确的 Vary；四语显式入口不受自动语言跳转干扰。尾斜杠、跟踪参数、无效路由和重复参数的规范化或错误响应有实际记录。
- AC4：补足 Open Graph／Twitter 图片及语言，图片为可抓取的固定品牌 PNG，1200×630，四语替代文本与标题对应；不含精确位置、问答或未核实天气，不请求天气或外部字体。不把分享标记等同于 Google 富结果资格。
- AC5：404、demo、坐标页、API 和首次天气无可用快照分别有合理索引策略；验证无快照／恢复／旧快照过程。首页有独立服务说明时继续允许索引；城市失败页不能被当作有效天气页。保留交互重试与手动搜索，避免单次 SSR 重复上游请求。
- AC6：本次 Node 回归、生产 HTTP／现有 CA 验证的 HTTPS、浏览器导航及必要受控故障验收；独立记录证据、取舍和外部门禁，更新 `qa/LOCAL-VERIFICATION.md` 与源码 ZIP，校验归档完整性／实际环境密钥排除／哈希；保持生产服务可访问。
