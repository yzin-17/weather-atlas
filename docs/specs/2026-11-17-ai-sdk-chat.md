# Web 对话接入 Vercel AI SDK

## 验收约定

- AC1：Web 使用 AI SDK 的 `useChat` 管理消息、发送、重试与停止。对话历史可见，已有提问后隐藏推荐问题，保留发送清空与草稿保护。
- AC2：`/api/ask` 在 Web 请求 SSE 时使用 SDK UI Message Stream 协议，计算期间发送进度，校验完成后发送回答文本与结构化预报依据；原 JSON 调用兼容。
- AC3：失败显示四语错误与手动重试；409 先刷新对应城市快照再重试，429 不自动反复调用。重试替换失败回答，不重复插入问题，不覆盖新草稿。
- AC4：用户可停止生成。浏览器取消请求后，服务端取消尚在进行的模型请求，不提交中断回答的城市上下文；可继续提问或重新生成。共享天气缓存任务保留，不因单个对话中断破坏其他请求。
- AC5：保留当前城市、其他城市单城追问、双城比较与对应城市的小时／日期依据。四语、桌面／窄屏、失败、中断、真实模型与规则模式有实际验证；构建后更新本地 HTTP／HTTPS 服务。
- AC6：前端将已收到的回答按 Unicode 字素逐步显示，不增加模型调用。网络已结束而文字尚未展示完时仍可停止；停止后保留已显示文字，后续文字不再出现。重试、后续提问、收起重开和历史依据正常，系统要求减少动画时直接显示完整回答。

## 边界与取舍

模型继续只提取意图，数值及回答由服务端天气快照计算。SSE 提供真实进度与校验后的文本／依据；不增加第二次模型改写调用。2026-11-17 用户追加前端逐字显示：延时仅存在于浏览器展示层，停止可冻结已显示前缀；完整显示后开放该回答依据，减少动画偏好直接显示。已完成且经过校验的城市上下文保留，仍在上游等待时的中断继续不提交上下文。不把意图 JSON 的片段作为天气结论。浏览器消息不持久化到服务端，不向模型额外发送整段对话正文，沿用经服务端校验的城市上下文。凭据继续保存在本地私有配置。
