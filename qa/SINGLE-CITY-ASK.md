# 指定城市单城问答验收与取舍

验收日期：2026-11-17。规格见 [单城问答](../docs/specs/2026-11-17-single-city-ask.md)。在现有未提交工作区上增量修改，未执行 Git 提交，私有模型配置保持在本地。

## 可复现路径

打开 `http://localhost:3300/zh-Hans/weather/seoul-1835848`，进入“问天气”，依次输入：

1. 今天广州天气怎样
2. 明天呢
3. 那下午呢
4. 会下雨吗

回答标明广州与 `Asia/Shanghai`。前两轮显示相应当地日期的最低／最高温及日期依据；后两轮保留广州、明天下午 12–17 点，分别回答温度与降水。点击依据打开广州日期或小时预报，返回后可以继续追问。页面主体仍是首尔；推荐问题在首次提问后保持隐藏。

## 实现位置与取舍

- `web/lib/single-city.ts`：新增单城编排，复用天气服务、全球搜索及现有计算函数。内置目录使用已知坐标，目录外城市使用搜索结果；只接受唯一匹配，未知或同名歧义返回明确错误，不采用模型给出的坐标或天气数字。
- `web/lib/ask.ts`：仍每轮只调用一次模型，提取城市、指标和时段，沿用 `gpt-6-luna`、350 token 输出上限与关闭额外推理的设置。指定其他城市不再直接归为不支持。服务端继续生成四语回答并计算数值。
- `web/lib/types.ts`、`contracts.ts`：新增独立 `singleContext`／`singleForecast`。保留双城比较 `context` 的既有含义，避免把逐日单城查询塞入只支持两城时段比较的契约。
- 上下文绑定页面原坐标、目标城市、版本、计划与日期锚点。服务端重新搜索验证城市，使用天气快照的真实时区；跨午夜不会把原日期静默挪到下一天。原页面或目标快照版本过期返回 409，目标版本检查在模型调用前执行；缺测不插值、不视为零降水。
- `web/components/AskDialog.tsx`：传回单城上下文，刷新时更新目标版本及原页面预报；日期与小时依据在弹窗内打开对应城市快照。回答切换到双城比较时清除单城上下文，返回当前地点时不延续其他城市。
- 无密钥规则模式支持明确的四语城市查询模板、目录别名及基本追问，复用同一搜索与数值校验。它不具备模型对任意自然语言的完整理解；歧义时要求用户补充城市或区域。
- 本轮交付为 Web 弹窗和服务端能力；未生成原生安装包或修改原生客户端的上下文传递。

## 失败与修复记录

首次真实模型验收的第三轮“那下午呢”仍返回 `daily/days`，没有遵守下午时段。新增服务端检查：对支持的明确时段按既有规则解析，并保留城市、当地日期及指标；将该错误输出写入回归样本，避免仅依赖提示词。原始失败响应保留在 `qa/evidence/single-city-model-failed-afternoon.json`。

首次替换候选构建后仅停止了启动包装进程，Next 监听子进程仍在，第二次检查读取到旧行为。随后按端口核对实际监听进程及工作目录，停止旧子进程、加载新构建，再完成验收。失败请求计入实际模型调用总数。

规则模板回归曾把英文普通问句和韩文“未来几天”误当城市；修正模板并通过既有四语快捷问题回归。类型检查也发现新 QA 脚本中的局部类型缺口，已修复，未关闭严格检查。
