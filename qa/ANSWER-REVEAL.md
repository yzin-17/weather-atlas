# Web 回答逐字显示验收与取舍

执行日期：2026-11-17（Asia/Shanghai）。范围：用户追加的前端逐字效果、停止展示、测试与日常服务更新；对应 [AI SDK 规格 AC6](../docs/specs/2026-11-17-ai-sdk-chat.md)。

## 实现与操作

打开 `http://localhost:3300/zh-Hans/weather/seoul-1835848`，进入“问天气”，发送问题。上游查询期间保持原 SSE 进度提示；收到回答后，浏览器逐步显示文字，右下角保持停止按钮。文字还没显示完时点击停止，当前前缀保持不变，未显示的部分不再补齐；可以继续提问或手动重试。

- `web/components/use-answer-reveal.ts` 管理每条 SDK 回答的独立展示进度，使用 `requestAnimationFrame` 与 `Intl.Segmenter` 按 Unicode 字素切分，保留 emoji 家庭序列、国旗、韩文与组合重音的完整性。通常每字约 24 ms；长回答加速，已收到完整文本的展示预算约 6 秒。后台页面恢复时按经过的时间推进，不积压定时器。
- `web/components/AskDialog.tsx` 将网络等待与文字展示合并为忙碌状态。网络已经结束时，停止按钮仍有效；停止会取消展示帧并调用 SDK `stop()`，等待模型期间仍沿用上游取消链路。停止状态持续到下一次主动发送或重试，已停止的历史回答保持原前缀。
- 逐字效果只作用于回答文字。完整展示后才显示该条回答的预报依据；停止的未完整回答不展示依据。已有完整回答、城市预报预览与返回行为保持有效；自动滚动跟随展示进度，用户上翻阅读时保留位置。
- `web/lib/ui-text.ts` 增加四语“正在显示回答”状态。系统 `prefers-reduced-motion: reduce` 时直接展示完整回答；回答区使用 `aria-busy`，减少逐字更新对辅助阅读的干扰。

## 取舍

1. 本次按用户要求增加浏览器展示延时，服务端 SSE、模型请求和天气计算均未修改。逐字显示不等于供应商的逐 token 生成；每次正常提问的模型调用数保持原路径，没有添加改写、补全或自动重试请求。本轮自动化外部模型调用总数为 0。
2. 停止分别覆盖上游等待和本地展示两个阶段。网络尚在进行时继续取消请求；网络已经完成时仅冻结本地显示，无法撤回已经完成的服务端工作。后者的城市上下文已经过校验，保留供连续追问使用；前者仍不提交中断请求的上下文。
3. 为避免把不完整展示与完整依据混在一起，当前回答显示完整后才开放依据。停止后保持已见文字；手动重试沿用 SDK 重新生成语义，会重新请求服务端，与既有重试行为相同。单纯逐字播放、停止或收起重开不会发起模型调用。
4. 采用按字素、按帧批量更新；高刷新率设备不依赖每帧一个字，长文本加速，减少动画偏好直接展示。动画状态与 SDK 原始消息分开，未修改答案数值、快照或证据。
5. 实现时检查了“模型等待很久后才收到文本”的情况：展示时钟在新的可展示文本到达时开始，不把上游等待时间计入逐字预算，避免一收到回答便跳到全文。停止状态覆盖后续晚到片段，下一次主动发送才恢复新回答展示。

## 服务与复现

当前日常入口：[本机 Web](http://localhost:3300/zh-Hans)、[局域网 HTTP](http://192.168.5.22:3300/zh-Hans)、[手机 HTTPS](https://192.168.5.22:3443/zh-Hans)。手机需同一局域网并信任本机 CA，见 [本地 HTTPS](LOCAL-HTTPS.md)。启动命令仍为 `npm --prefix web start -- --hostname 0.0.0.0 --port 3300` 与 `npm run dev:https`。本轮没有修改密钥、模型选择或启动配置。
